# TaskFlow 里程碑报告 · M3 通知与事件链路

> 依据：[实施计划 v1.0](实施计划-v1.0.md) 第 5 章 | 前置：[M2 里程碑报告](里程碑-M2-任务核心.md)

## 1. 里程碑目标

打通 RabbitMQ 事件链路：任务域事件 → notification-service 消费 → 站内消息 + 邮件；站内消息接口与前端通知中心；API Key 鉴权链路。

## 4. 踩坑与修复记录

| 问题 | 处理 |
|---|---|
| 事件载荷原本缺 eventId（event_id 由 DB 默认生成且不随消息下发），消费端无法幂等 | task-service `writeOutbox` 改为在事务内生成 UUID，同时写 event_id 列与完整事件信封；新增 StringUuidTypeHandler（String↔UUID 列） |
| Instant 序列化失败 | TaskService 的 ObjectMapper 注册 JavaTimeModule |
| Feign 缺 loadbalancer | notification-service 补 spring-cloud-starter-openfeign + spring-cloud-starter-loadbalancer |
| 权限缓存冷启动缺口 | auth-user-service 增加 ApplicationReadyEvent 权限缓存预热（网关 API Key 链路 taskAdmin 角色首调曾被误判 3001） |
| 网关回源失败空响应 | ApiKeyAuthFilter 用 switchIfEmpty 兜底，fail-closed |

## 5. 已知限制（移交后续里程碑）

1. 消费端失败只记日志不重投（无毒消息死循环风险，但也无死信补偿）；后续可接 DLQ。
2. processed_event 主键仅 event_id：M5 stats-service 接入消费时需改为 (event_id, consumer) 复合键。
3. 定时事件 task.due.soon / task.overdue 的拓扑与消费端已就绪，生产者扫描器属 M5。
4. 邮件正文为纯文本摘要，HTML 模板未做（SMTP 凭据走 SMTP_* 环境变量）。

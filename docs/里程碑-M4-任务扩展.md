## 4. 踩坑与修复记录

| 问题 | 处理 |
|---|---|
| Spring multipart 默认 1MB 会拦掉合规附件 | application.yml 显式 max-file-size=20MB / max-request-size=25MB;容器级超限由 AttachmentExceptionHandler 转 2008 |
| 评论/附件创建后 createdAt 为 null(DB 默认值不回填) | insert 后回查 |
| 导入失败批次记录会随整批回滚丢失 | ImportBatchRecorder 用 REQUIRES_NEW 独立事务留痕 |
| 导入标题长度与 create() 口径不一致(任务书 200 vs create 100) | 按 create() 的 ≤100 校验,保证"校验通过即可入库"契约 |

## 5. 已知限制(移交后续里程碑)

1. 导入任务的 source 字段沿用 create() 写死的"网页"(PRD 要求记"Excel 导入",TaskService.create 签名未动,后续可加重载)。
2. 导入行进度只校验不写入(任务固定从 0 起步,符合"从待办起步"语义)。
3. 文件级 1001(非 xlsx/空/>500 行)不落 import_batch(受表 CHECK 0..500 约束所限)。
4. 导出性能:当前一次性查询,超大数据量需分页流式(已有 10000 行上限 2010 兜底)。

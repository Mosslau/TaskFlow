## 项目数据库（2026-09-08 本机已创建 ✅）

后端四个服务使用 PostgreSQL 的四个业务库（owner: postgres），由各自 Flyway 在首次启动时自动迁移建表：

| 库 | 服务 | 迁移产物 |
|---|---|---|
| `auth_user_db` | auth-user-service | 表 + 种子（3 角色、42 行权限、初始 admin / Admin@123 首登强制改密） |
| `task_db` | task-service | 表（**pg_trgm 扩展已启用**，V1 迁移用 `gin_trgm_ops` 建索引） |
| `notification_db` | notification-service | 表 |
| `stats_db` | stats-service | 表 |

原文档「已创建」描述的是原机器状态；换机后本机原本没有这四个库，已于 2026-09-08 重新创建（含 task_db 的 pg_trgm 扩展），同日启动后端后 **Flyway 已执行完成**：

- 表：`auth_user_db` 7 张、`task_db` 7 张、`notification_db` 4 张、`stats_db` 5 张（合计 23 张，含各库 `flyway_schema_history`）
- 种子数据：3 角色、42 行权限矩阵（`role_permission.permission_key`）、初始 admin（Admin@123，`must_change_password=TRUE` 首登强制改密）、1 个默认部门

## 开发环境启动顺序

1. 确认中间件运行：`brew services list`（postgresql@18 / redis / rabbitmq）+ Nacos（`sh ~/Downloads/nacos/bin/startup.sh -m standalone`，**勿重复启动**，会报 8848 被占；有残留进程先 `lsof -nP -iTCP -sTCP:LISTEN | grep java` 查看并 kill）
2. 启动后端：`cd TaskFlow && ./start.sh`（网关 8000 + 四个业务服务 8081-8084；首次需先 `mvn install -N` + `mvn install -pl common`）
3. 前端：`cd frontend && pnpm dev`（代理已指向网关 8000）

## 应急：忘记管理员密码

admin 忘记密码时的恢复路径（内网单机部署，直接改库）：

```bash
# 重置为 Admin@123（must_change_password=TRUE，登录后强制改密）
PGPASSWORD=root psql -h 127.0.0.1 -U postgres -d auth_user_db -c \
"UPDATE app_user SET password_hash='\$2y\$10\$yQBFrOqebPqT2IVrlWx2ZuxG2N9ReAO7qo05/.2NRMOS5TMg93Xk.', must_change_password=TRUE WHERE account='admin';"
```

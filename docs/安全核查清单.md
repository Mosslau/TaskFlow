## 2. 逐项证据

### 2.1 密码 BCrypt 存储（通过）

- 种子 SQL：`auth-user-service/src/main/resources/db/migration/V2__seed_auth_user.sql` 中 admin 初始密码为 `$2y$10$yQBFrOqebPqT2IVrlWx2ZuxG2N9ReAO7qo05/.2NRMOS5TMg93Xk.`（BCrypt，cost=10，带盐）。
- 代码：`CommonBeansConfig.passwordEncoder()` 注册 `BCryptPasswordEncoder`；`AuthService.login` 用 `passwordEncoder.matches`（恒定时间比较）。
- 库内实测：`app_user.password_hash` 全部 `$2y$10$…` 前缀；接口不返回 hash（`AppUser` 序列化忽略）。
- 改密 API `PUT /auth/api/v1/password` 用 BCrypt 重编码。

### 2.2 登录失败锁定 15 分钟（通过，实测）

实测（临时账号 `locktst01`，6 次错密）：

| 尝试 | HTTP | code | message / details |
|---|---|---|---|
| 1~4 | 401 | 3002 | 账号或密码错误，`remainingAttempts` 4→1 |
| 5 | 401 | 3003 | 账号锁定中（15 分钟） |
| 6 | 401 | 3003 | 同上（锁定期内正确密码亦拒绝） |

Redis 实测：`auth:lock:locktst01 = 1`，**TTL = 900 s**（15 分钟，代码 `LOCK_TTL=Duration.ofMinutes(15)`）；失败计数键 `auth:fail:{account}` 在达 5 次后随锁定清除。测试后临时账号已停用清理、锁定键已删除。

### 2.3 JWT / 刷新令牌 / 旧令牌失效（通过，附改进）

- 配置：`taskflow.jwt.ttl: PT2H`（各服务 application.yml）；刷新令牌 7 天 `REFRESH_TTL`（AuthService）；登出与改密时 `redis.set("auth:blacklist:"+token, …, 2h)` + 删除 `auth:refresh:{userId}`。
- Redis 实测存在 `auth:blacklist:*` / `auth:refresh:{userId}` 键。
- **改进项（§5.2）**：JWT 载荷仅 `sub/roleKey/iat/exp`，无 `jti`；`iat` 秒级粒度导致"改密后同一秒内重新登录"会生成与已拉黑令牌**逐字节相同**的 JWT（实测复现，表现为新登录令牌立即 3005）。修复建议：签发时加入随机 `jti` 或毫秒 `iat`。

### 2.4 鉴权与越权（通过，实测：基线 + 6 组越权）

网关 `JwtAuthFilter`（Bearer JWT，校验黑名单+过期）+ `ApiKeyAuthFilter`（X-API-Key，仅放行 `POST /task/api/v1/tasks`）；服务端 `AuthInterceptor` + `@RequirePerm` 二次校验；任务级可见性在 `TaskService.mustVisible/page` 统一过滤（不可见与不存在同返回 2001，防探测）。

普通用户（user 角色，只有 `viewAssigned/updateAssigned/transferAssigned`）实测：

| 用例 | 结果 |
|---|---|
| 基线：读本人被指派任务详情 | ✅ 200 |
| 越权①：读他人任务（非本人创建/处理） | HTTP **403** code **2001** 任务不存在或不可见 |
| 越权②：改本人名下任务优先级（缺 prioOwn） | HTTP **403** code **3001** 缺少权限点 prioOwn |
| 越权③：创建任务（缺 create） | HTTP **403** code **3001** 缺少权限点 create |
| 越权④：删除 admin 评论（非评论人/非 admin） | HTTP **403** code **3001** 仅评论人本人或 admin 可删除评论 |
| 越权⑤：编辑他人创建的任务（缺 editOwn） | HTTP **403** code **3001** 缺少权限点 editOwn |
| 越权⑥：对他人任务提交验收（不可见） | HTTP **403** code **2001**（可见性拦截） |

越权一律 HTTP 403（满足 PRD 验收"越权访问他人任务返回 403"），业务码区分 2001（不可见）/3001（缺权限）。

### 2.5 SQL 注入（通过）

- 全部查询走 MyBatis-Plus `LambdaQueryWrapper`/`QueryWrapper` 参数化；仓库（排除 .m2/node_modules/target/logs/.git/.dsh）无 XML 手写 SQL（仅 logback 配置），无 `jdbcTemplate`/字符串拼 SQL；检索无 `${}` 出现在 SQL 上下文。
- LIKE 关键字经参数绑定；用户输入均有长度/枚举约束（标题 ≤100、评论 ≤500、描述 ≤2000、枚举白名单）。

### 2.6 XSS（通过）

- 前端 `frontend/src` **全站无 `v-html` / innerHTML / document.write**（grep 为空）——Vue mustache `{{ }}` 默认转义。
- 用户输入渲染点均为纯文本插值：评论 `TaskCommentSection.vue`（`{{ c.content }}`）、时间线 note、审计 `changeDetail` 等。
- 后端对纯文本输入仅校验长度，不存 HTML 富文本；CSV 导出对含逗号/引号/换行字段做 RFC4180 转义（`csvEscape`），防公式注入同时保证 Excel 打开正确。
- 附件上传扩展名白名单（`TaskAttachmentService`：pdf/doc/docx/xls/xlsx/ppt/pptx/txt/md/png/jpg/jpeg/zip/rar/7z，大小写不敏感）+ ≤20MB/≤10 个校验（2008），病毒扫描属一期排除项（PRD 9，依赖终端安全体系）。

### 2.7 关键接口限流（未实现 —— 上线前必须补）

- 证据：错误码 `ErrorCode.RATE_LIMITED(1003, "触发限流", 429)` 已定义，但全仓 grep `RateLimit/限流/RequestRateLimiter/bucket` 仅命中注释与文档；网关 `application.yml` 无 `RequestRateLimiter` 过滤器，gateway-service 只有 `JwtAuthFilter/ApiKeyAuthFilter` 两个过滤器。
- 修复建议（上线前）：网关加 Spring Cloud Gateway `RequestRateLimiter`（RedisRateLimiter，键=客户端 IP 或账号，如登录 `/auth/api/v1/login` 建议按 IP 5~10 次/分钟、写接口按账号限流），命中时返回 429 + `code:1003`；或前端再加 Nginx `limit_req` 兜底。**本期如实标注未实现，不改代码。**

### 2.8 敏感配置（通过 —— 仓库无真实密钥；开发默认明文上线前覆盖）

仓库级 grep（排除 .m2/node_modules/target/logs/.git/.dsh/.cache/.pids）结果：

| 位置 | 内容 | 判定 |
|---|---|---|
| 5 个服务 `src/main/resources/application.yml` | `password: root`（本地 PostgreSQL/Redis）、RabbitMQ `guest/guest`、`secret: ${JWT_SECRET:taskflow-dev-secret-please-override}` | ⚠️ 开发默认明文，**可被占位默认值覆盖**；不入真实密钥 |
| 业务 Java 代码 | 无任何密钥硬编码（grep JWT_SECRET/密码/私钥关键字为 0） | ✅ |
| SMTP | notification-service 全部 `${SMTP_HOST:localhost}` 等环境变量占位，默认空口令 | ✅ |
| `deploy/.env.example` | 明确列出生产必改项（JWT_SECRET/POSTGRES_PASSWORD/REDIS_PASSWORD/RABBITMQ_PASSWORD），注释"密钥只经环境变量注入，绝不写入代码库/镜像" | ✅ 模板安全；`.env` 不入库（deploy/.gitignore） |
| 文档/种子 SQL | 出现开发口令 `Admin@123`（仅开发环境、must_change_password=TRUE） | 开发约定，生产初始密码须由部署脚本随机生成覆盖（V2 种子注释已声明） |

**上线前必须用环境变量覆盖的默认值**（否则生产使用同一开发密钥/口令）：
`JWT_SECRET`（5 服务一致，`openssl rand -base64 48`）、`POSTGRES_PASSWORD`、`REDIS_PASSWORD`、`RABBITMQ_USER/PASSWORD`、SMTP 凭据（如启用邮件）、Nacos 鉴权开关（如对外暴露）。

### 2.9 HTTPS（部分 —— 需生产补 TLS）

- 现状：仓库无任何 TLS 证书/443 配置；开发与部署 nginx 均监听 **8080 HTTP**（`deploy/nginx.conf`：`listen 8080;`，反代到 127.0.0.1:8000）；容器版前端 nginx 同理。内网允许"网关终止 TLS"（PRD 7.3.6），当前未落地。
- 建议生产 nginx 片段（前端站点 443 终止 TLS → 反代网关）：

```nginx
server {
    listen 443 ssl;
    server_name taskflow.example.com;
    ssl_certificate     /etc/nginx/certs/taskflow.crt;
    ssl_certificate_key /etc/nginx/certs/taskflow.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;
    ssl_session_cache shared:SSL:10m;
    client_max_body_size 25m;
    root   /opt/taskflow/deploy/artifacts/frontend-dist;
    index  index.html;
    location / { try_files $uri $uri/ /index.html; }
    location /auth/ { proxy_pass http://127.0.0.1:8000; proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; }
    location /task/ { proxy_pass http://127.0.0.1:8000; proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; }
    location /notification/ { proxy_pass http://127.0.0.1:8000; proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; }
    location /stats/ { proxy_pass http://127.0.0.1:8000; proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; }
}
server { listen 80; server_name taskflow.example.com; return 301 https://$host$request_uri; }
```

### 2.10 API Key（通过，实测）

库表 `api_key` 列：`key_hash / key_prefix / status / last_used_at`（无明文列）。实测：

| 步骤 | 结果 |
|---|---|
| 签发 `POST /auth/api/v1/api-keys`（绑定 taskAdmin 服务账号 svc_openapi） | 200，响应 `apiKey: "tfk_273ad1e6…"` 明文**仅此一次**（36 位） |
| 库内形态 | `key_hash == sha256(明文)` ✅；`key_prefix == 明文前8位(tfk_273a)` ✅；status=active |
| 网关用 Key 调 `POST /task/api/v1/tasks` | ✅ 200，creator=svc_openapi |
| Key 访问未开放路径（GET /tasks） | HTTP **403** code **3010** 仅开放 POST create |
| 伪造 Key | HTTP **401** code **3006** |
| Key 列表 `GET /auth/api/v1/api-keys` | 仅返回 `keyPrefix`，无明文/无 hash ✅ |
| 停用后立即调用 | HTTP **401** code **3006**（缓存主动失效，即时生效）✅ |

Key 与 JWT 互斥（同时携带返回 1004）；重生成后旧 Key 立即失效（旧哈希网关缓存删除）。

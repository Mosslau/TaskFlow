## 1. 健康检查与探针(Actuator)

五个服务均已引入 `spring-boot-starter-actuator`,直连各自端口即可访问(无需鉴权,已加入放行清单):

| 端点 | 用途 |
|---|---|
| `GET /actuator/health` | 聚合健康(含 db / rabbit / redis / discovery 明细) |
| `GET /actuator/health/readiness` | **就绪探针**(k8s readinessProbe 用,精简体) |
| `GET /actuator/health/liveness` | **存活探针**(k8s livenessProbe 用,精简体) |
| `GET /actuator/metrics` | 指标名与取值查询 |
| `GET /actuator/info` | 应用信息 |
| `GET /actuator/prometheus` | **Prometheus 抓取端点** |
| `POST /actuator/refresh` | 配置热刷新(网关已暴露,用于手动触发) |

```bash
curl -s localhost:8082/actuator/health            # {"status":"UP",...}
curl -s localhost:8082/actuator/health/readiness  # {"status":"UP"}
curl -s localhost:8082/actuator/prometheus | head # jvm_/http_server_/process_ 指标
```

Prometheus 抓取配置示例:

```yaml
scrape_configs:
  - job_name: taskflow
    metrics_path: /actuator/prometheus
    static_configs:
      - targets: ["host:8000","host:8081","host:8082","host:8083","host:8084"]
```

> 说明:`/actuator/**` 已加入网关过滤器与各服务 `AuthInterceptor` 白名单(探针不鉴权、不计限流)。生产部署建议只在内网暴露,或改为独立管理端口。

## 2. 链路追踪 traceId

- **网关** `TraceIdFilter`(order=HIGHEST_PRECEDENCE):优先取请求头 `X-Trace-Id`,缺失则生成 UUID;写入请求头透传下游 + 回写响应头;并输出一条 INFO 日志(method / path / status / cost / traceId)
- **四个 servlet 服务** `TraceIdFilter`:`MDC.put("traceId", …)`,请求结束清理
- **日志格式**(5 个服务统一的 `logback-spring.xml`,控制台 + 文件双输出):
  `%d{yyyy-MM-dd HH:mm:ss.SSS} %-5level [%X{traceId:-}] [%thread] %logger{36} : %msg%n`
- 日志文件落点:`<module>/logs/<service>.log`,按天滚动 `maxHistory=30` + `totalSizeCap=1GB`

```bash
# 跨服务串联示例
curl -i -H 'X-Trace-Id: demo-123' -X POST localhost:8000/task/api/v1/tasks \
     -H 'Authorization: Bearer <jwt>' -H 'Content-Type: application/json' \
     -d '{"title":"trace demo","taskType":"日常事务","priority":"P2","assigneeId":2}'
# 响应头: X-Trace-Id: demo-123
grep 'demo-123' gateway-service/logs/gateway-service.log task-service/logs/task-service.log
```

## 3. Nacos 配置中心

### 3.1 接入方式

五个服务均引入 `spring-cloud-starter-alibaba-nacos-config`,并在 `application.yml` 声明两条可选配置(拉不到时回退本地默认值,不影响启动):

```yaml
spring:
  config:
    import:
      - optional:nacos:taskflow-common.yaml        # 全服务共享
      - optional:nacos:${spring.application.name}.yaml   # 服务专属
  cloud:
    nacos:
      config:
        server-addr: 127.0.0.1:8848
```

### 3.2 Nacos 中的配置(dataId / DEFAULT_GROUP / public)

| dataId | 内容 | 生效范围 |
|---|---|---|
| `taskflow-common.yaml` | `taskflow.ratelimit.*`(enabled / 用户 / IP 每分钟配额)、`logging.level.com.taskflow` | 全部服务共享 |
| `gateway-service.yaml` | **仅**放置网关真正需要覆盖的键;当前无需覆盖,故不定义 `taskflow.ratelimit.*` | 网关 |

> **密钥类配置不入 Nacos**:JWT_SECRET、数据库/Redis/RabbitMQ/SMTP 口令仍走环境变量(见 `deploy/.env.example`),保持"密钥只经环境变量注入"的约束。

### 3.3 动态刷新(已实测)

`RateLimitFilter` 标注 `@RefreshScope`,Nacos 推送后自动刷新(无需重启):

```
[Nacos Config] Load config[dataId=taskflow-common.yaml, group=DEFAULT_GROUP] success   # 启动加载
[Nacos Config] Listening config: dataId=taskflow-common.yaml                          # 注册监听
Refresh keys changed: [taskflow.ratelimit.ip-per-minute]                              # 配置改动推送
```

**优先级陷阱(2026-09-11 实测,必读)**:`spring.config.import` 导入的配置**优先级低于**发起导入的本地文档,且**后导入的 dataId 高于先导入的**。同名键因此会被遮蔽,表现为"配置中心改了不生效、`POST /actuator/refresh` 返回 `[]`"。两类遮蔽都要避免:

1. 各服务 `application.yml` 不得定义与 Nacos 相同的键 —— `taskflow.ratelimit.*` 已从 `gateway-service/src/main/resources/application.yml` 移除(代码内 `@Value` 默认值 true / 300 / 600 兜底,Nacos 不可用时不影响启动);
2. `gateway-service.yaml` 不得重复定义 `taskflow-common.yaml` 已有的键 —— 它 import 更晚,会覆盖公共配置。

**实测过程**:`ip-per-minute` 由 600 改为 **2**(不重启)→ 日志出现 `Refresh keys changed: [taskflow.ratelimit.ip-per-minute]` → 连打匿名登录,第 3 次起 **429 + code 1003**(`details.retryAfterSeconds`);改回 **600** 后同样热生效,请求恢复正常。

### 3.4 发布/修改配置

本机已把 `~/Downloads/nacos/conf/application.properties` 的 `nacos.core.auth.console.enabled` 置为 `false`(改动后需重启 Nacos),因此可直接用**控制台 API 免登录**发布;若该开关为 `true`,`/v3/console/*` 会返回 `403 access denied`(client API `/nacos/v3/client/cs/config` 只读,`POST` 返回 `405`)。发布方式:

```bash
curl -X POST http://127.0.0.1:8080/v3/console/cs/config \
  --data-urlencode "dataId=taskflow-common.yaml" \
  --data-urlencode "groupName=DEFAULT_GROUP" \
  --data-urlencode "namespaceId=public" \
  --data-urlencode "type=yaml" \
  --data-urlencode "content=$'taskflow:\n  ratelimit:\n    user-per-minute: 300\n    ip-per-minute: 600'"
```

也可直接在控制台 http://localhost:8080 → 配置管理 中图形化编辑。

## 4. 创建任务幂等(Idempotency-Key)

`POST /task/api/v1/tasks` 支持可选请求头 `Idempotency-Key`:

| 场景 | 行为 |
|---|---|
| 不带该头 | 行为与改造前完全一致 |
| 同用户 + 同 Key(24h 内) | **不新建**,回放首次结果(同一 taskId,响应逐字段一致) |
| 并发同 Key | Redis `setIfAbsent` 抢占 + 50ms×2s 轮询;等到结果则回放,超时返回 **409 / code 2014** |
| Key 空串 / >200 字符 | **1001** |
| 记录指向的任务已被删除 | **404 / code 1002**(不新建) |

- 键设计:`task:idem:{userId}:{sha256(Key)}`(原文不落库,跨用户隔离);成功记录 TTL 24h,占位 TTL 60s
- 前端:创建任务/子任务提交时生成 `crypto.randomUUID()` 作为 Key,失败重试复用同一 Key,成功后重置

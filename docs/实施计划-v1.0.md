## 1. 总览

### 1.1 里程碑划分

| 里程碑 | 主题 | 核心产出 | 依赖 |
|---|---|---|---|
| M0 | 工程脚手架 | 可启动的 5 服务空壳 + 前端工程 + 本地中间件 | — |
| M1 | 认证与用户域 | 登录/用户/角色/权限矩阵可用，网关鉴权贯通 | M0 |
| M2 | 任务核心 | 任务 CRUD + 状态机 + 可见性 + 时间线，列表与抽屉可用 | M1 |
| M3 | 通知与事件链路 | RabbitMQ 事件贯通，站内消息 + 邮件触达 | M2 |
| M4 | 任务扩展 | 评论/附件/子任务/日程/导入导出 | M2（可与 M3 并行） |
| M5 | 统计与定时任务 | 统计预聚合 + 定时扫描 + 统计/日程前端 | M3 |
| M6 | 联调验收与上线 | 16 条验收条件全过，部署脚本就绪 | M4、M5 |

### 1.2 通用约定

1. 每个里程碑后端先按接口设计文档落契约（Controller + DTO 骨架），前后端再并行开发。
2. 每个服务交付即带：单元测试（状态机/权限/口径计算）、Testcontainers 集成测试（鉴权与可见性越权用例为必选项）。
3. 数据库变更以迁移脚本管理（Flyway），初始脚本 = 库表设计文档全部 DDL + 种子数据。
4. 代码结构遵循架构文档第 6 章 Monorepo；前端视觉遵循 UI 设计规范（Element Plus 主题变量先行配置）。
5. 每里程碑结束打 git tag（`m0-scaffold` … `m6-release`），可独立演示。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 事件乱序导致 stats 聚合偏差 | 消费者幂等 + 事件带时间戳；M5 预留每日对账任务接口（一期可先手动触发） |
| 本地文件系统附件在演示环境不可共享 | M0 起即用配置化存储路径；多实例前按架构 2.4 切 NFS/对象存储 |
| 微服务本地调试链路长 | M0 的 Compose 环境 + 网关单点入口；支持单服务独立起依赖 |
| 前端 Element Plus 主题与原型偏差 | M0 先落主题变量，M1 起每页对照 `docs/ui/` 原型走查 |

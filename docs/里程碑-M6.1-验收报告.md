## 3. 缺陷清单（产品缺陷，未改主工程）

### 缺陷 #1（ACC-11 失败）：Excel 导入任务来源渠道写死「网页」
- **现象/断言**：`POST /task/api/v1/tasks/import` 成功批次 `batchId/totalRows/successCount` 正确，任务正常入库并触发指派，但 `task.source` = `网页`，期望 PRD 4.7/接口契约 = `Excel 导入`。
- **复现**：admin 下载 `GET /task/api/v1/tasks/import-template`，用 POI 填两行合法数据（处理人=有效账号），上传导入 → `SELECT source FROM task WHERE title LIKE 'ACCIMP-%'` 全部为 `网页`。
- **代码位置**：`task-service/.../TaskService.create` 顶层任务分支硬编码 `task.setSource("网页")`；`ImportExportService.importExcel` 未做来源覆写（M4 报告「已知限制 1」原样遗留）。
- **建议**：`create(...)` 增加 `source` 入参或新增 `createWithSource` 重载（只增不改），导入路径传 `Excel 导入`，OpenAPI 路径传 `OpenAPI`；为已入库数据可补一次订正脚本。

### 缺陷 #2（ACC-16 失败）：任务列表/详情项缺少 `parentTaskNo`（父任务编号）
- **现象/断言**：子任务创建成功后，`GET /task/api/v1/tasks?keyword=<子任务标题>` 与 `GET /tasks/{id}` 的列表项/详情任务对象仅有 `parentId`，**无 `parentTaskNo`**；接口文档 list item schema 明确含 `parentId,parentTaskNo`；前端 `TaskListView.vue:575`/`TaskDetailDrawer.vue:373` 都依赖 `row.parentTaskNo` 渲染 `[父编号]`/父编号徽标 → 前端树形列表实际展示不出父任务编号。
- **复现**：admin 建父任务 A（TSK-…）→ 建子任务 B（body.parentId=A.id）→ 列表关键字查 B，查看返回项 keys（实测仅 22 个字段，无 parentTaskNo）。
- **代码位置**：`TaskService.toItem` 未拼装父任务编号（列表与详情共用一个映射）。
- **建议**：`toItem` 补充 `parentTaskNo`（有 parentId 时回查父任务 task_no，或列表 SQL join/子查询批量补齐）；对应当前"树形展开按 parentId 懒加载"的前端模型。

### 附：环境/工程观察（非阻断，供排期参考）
1. **stats 预聚合漂移**：运行前 stats 聚合表与 task_db 明细严重不一致（如某日 total 1500+ vs 明细 ~7；涉及批量压测/样例数据导入与事件重复投递的遗留）。ACC-6/ACC-16 均先调用 admin `POST /stats/api/v1/rebuild` 校准后再比对，**重建后数值与手工 SQL 完全一致**。建议把 rebuild 纳入日常对账脚本。
2. **任务从属表无 FK 级联**：删除任务需先删 `task_timeline/comment/attachment`（本次套件清理即按此顺序），产品如需任务物理删除的级联语义可评估 DB 级 `ON DELETE CASCADE` 或服务层级联删除（父会话提及的 FK 级联计划与此吻合）。
3. **通知消费/邮件阻塞**：无 SMTP 时每封失败邮件占用消费线程约 7s（1s/2s/4s 退避），大批量事件会造成队列积压；本次套件临时用本地 SMTP sink（端口 2525，`/tmp/tfsmtp/inbox` 落盘证据）加速排空，**验证完毕后已把 notification-service 还原为无 SMTP 原配置**。

## 1. 通用约定

### 1.1 基础约定

| 项 | 约定 |
|---|---|
| Base Path | `/{服务模块}/api/v1/`，全部接口经 gateway-service 统一入口；模块前缀标识服务归属，`v1` 为接口版本（未来破坏性变更以 `v2` 并行） |
| 数据格式 | 请求与响应均 `application/json; charset=utf-8`（文件上传/下载除外） |
| 时间格式 | ISO 8601 UTC 字符串（`2026-09-05T10:00:00Z`）；东八区渲染在前端（PRD 7.4） |
| 资源标识 | 路径参数用内部 BIGINT id；`taskNo`（TSK-xxx）仅展示与搜索，不作路径参数 |
| 服务归属 | 网关按模块前缀路由：`/auth/api/v1/**` → auth-user-service；`/task/api/v1/**` → task-service；`/notification/api/v1/**` → notification-service；`/stats/api/v1/**` → stats-service |

### 1.2 统一响应信封

```json
// 成功
{ "code": 0, "message": "ok", "data": { } }
// 失败
{ "code": 2002, "message": "前置状态不满足，无法提交验收", "details": null }
```

1. `code = 0` 唯一表示成功；业务错误码分段：**1xxx 通用 / 2xxx 任务 / 3xxx 权限 / 4xxx 通知**（全表见第 6 章）。
2. HTTP 状态码与业务码配合：参数与业务规则错误 `400` + 业务码；未认证 `401`；无权限 `403`；资源不存在 `404`；服务端错误 `500`。**不用 200 包一切**。
3. `details` 承载结构化补充（如参数校验的逐字段错误、缺少的权限点），无补充时为 `null`。

### 1.3 分页与筛选

- 请求：`page`（默认 1）、`size`（10 / 20 / 50，默认 20）；筛选条件平铺为 query 参数。
- 响应：`data: { "list": [...], "total": 137, "page": 1, "size": 20 }`。
- 除显式注明外，列表默认按创建时间倒序。

### 1.4 认证方式

| 调用方 | 凭证 | 说明 |
|---|---|---|
| 浏览器前端 | `Authorization: Bearer <JWT>` | 登录签发（2h），过期用 `POST /auth/api/v1/refresh` 换新；登出/改密后旧令牌进 Redis 黑名单立即失效 |
| 外部系统（OpenAPI） | `X-API-Key: <key>` | 静态密钥，仅开放 `POST /task/api/v1/tasks`，见第 2 章 |

两种凭证互斥，同请求同时携带时网关按 400（1004）拒绝。

## 2. OpenAPI 接入（静态 API Key）

1. admin 在权限模块创建**专用服务账号**（角色固定 `taskAdmin`：可创建任务、仅可见自己相关任务），系统为其签发 API Key：`tfk_` + 32 位随机串。**Key 哈希落库，明文仅创建时响应一次**。
2. Key 可停用、可重新生成（旧 Key 立即失效）。
3. 网关识别 `X-API-Key` 后按绑定服务账号的身份走完全相同的权限点与可见性校验。
4. 通过 Key 创建的任务：`creator_id` = 绑定服务账号，`source` = `OpenAPI`，正常触发 `task.assigned` 事件通知处理人。
5. 一期 OpenAPI **仅开放 `POST /task/api/v1/tasks`**；其余接口携带 Key 凭证一律 403（3006）。
6. 库表支撑：本方案的 `api_key` 表归 `auth_user_db`（DDL 见库表设计文档第 3 章）。

### 2.1 API Key 管理接口（auth-user-service，权限点 manageUser）

| 方法与路径 | 说明 | 请求体 | 响应 data |
|---|---|---|---|
| POST /auth/api/v1/api-keys | 为服务账号签发 Key | `{ "userId": 12, "name": "运维监控系统" }` | `{ "id": 3, "apiKey": "tfk_...(仅此一次)", "createdAt": "..." }` |
| GET /auth/api/v1/api-keys | Key 列表（不含明文与哈希） | — | `[{ "id", "name", "userId", "keyPrefix": "tfk_a1b2", "status": "active", "createdAt", "lastUsedAt" }]` |
| PUT /auth/api/v1/api-keys/{id}/status | 停用 / 启用 | `{ "status": "disabled" }` | `{ "id", "status" }` |
| POST /auth/api/v1/api-keys/{id}/regenerate | 重新生成（旧 Key 失效） | — | `{ "id", "apiKey": "tfk_...(仅此一次)" }` |

### 3.1 认证

| # | 方法与路径 | 权限 | 请求体 | 响应 data |
|---|---|---|---|---|
| 1 | POST /auth/api/v1/login | 无 | `{ "account", "password" }` | `{ "token", "refreshToken", "expiresIn": 7200, "user": { "id", "name", "account", "roleKey", "permissions": ["create", ...], "mustChangePassword" } }` |
| 2 | POST /auth/api/v1/logout | 登录 | — | `null`（当前 JWT 进黑名单） |
| 3 | POST /auth/api/v1/refresh | 刷新令牌 | `{ "refreshToken" }` | `{ "token", "expiresIn": 7200 }`（**补充 PRD 缺失接口**：PRD 7.3.2 定了 7 天刷新令牌但未定刷新端点） |
| 4 | PUT /auth/api/v1/password | 登录 | `{ "oldPassword", "newPassword" }` | `null`（改密后旧令牌全部失效，`mustChangePassword` 置 false） |

密码规则：8–64 位，须含字母与数字。

## 4. task-service 接口

### 4.1 任务 CRUD 与列表

| # | 方法与路径 | 权限 | 说明 |
|---|---|---|---|
| 19 | GET /task/api/v1/tasks | 登录（服务端可见性过滤） | 见下方参数与响应 |
| 20 | POST /task/api/v1/tasks | create | 创建任务；body 含 `parentId` 即创建子任务 |
| 21 | GET /task/api/v1/tasks/{id} | 可见性规则 | 任务详情聚合 |
| 22 | PUT /task/api/v1/tasks/{id} | editOwn | 编辑任务字段 |
| 23 | DELETE /task/api/v1/tasks/{id} | deleteOwn | 删除（仅待办，二次确认在前端） |

**GET /task/api/v1/tasks 请求参数**（全部可选，AND 叠加，先经可见性过滤）：

| 参数 | 取值 | 说明 |
|---|---|---|
| keyword | 文本 | 匹配编号、标题、描述、创建人姓名、处理人姓名 |
| status | new/doing/wait/done/close | 单选 |
| priority | P0/P1/P2/P3 | 单选 |
| taskType | 6 类型之一 | 单选 |
| creatorId / assigneeId | 用户 id | 单选 |
| scope | all/mine/assigned/overdue | 快捷范围，与其他条件叠加 |
| page / size | 分页 | size 仅允许 10/20/50 |

响应 data（分页）：list 项 `{ "id", "taskNo", "title", "taskType", "priority", "status", "progress", "creatorId", "creatorName", "assigneeId", "assigneeName", "dueAt", "createdAt", "updatedAt", "parentId", "parentTaskNo" }`；子任务平铺返回，`parentTaskNo` 供前端渲染 `↳` 前缀；`dueAt` 逾期由前端标红。

**POST /task/api/v1/tasks 请求体**：

```json
{
  "title": "必填，1-100 字符",
  "description": "可选，≤2000 字符",
  "taskType": "项目开发（默认）",
  "priority": "P2（默认）",
  "assigneeId": 12,
  "dueAt": "2026-09-08T10:00:00Z",
  "progress": 0,
  "parentId": null
}
```

校验：处理人须为 taskAdmin/user 角色的在职用户，否则 `2007`；父任务非法（不存在/自身是子任务）`2011`。响应 data：创建后的完整任务对象（含 `taskNo`）。创建成功触发 `task.assigned`。

**PUT /task/api/v1/tasks/{id} 请求体**：title、description、taskType、priority、assigneeId、dueAt、progress（全可选，提交即改）；变更处理人触发通知新处理人。已归档任务返回 `2005`。

**GET /task/api/v1/tasks/{id} 响应 data**（详情抽屉一次取全）：

```json
{
  "task": { "...全部字段" },
  "timeline": [{ "id", "operatorName", "action", "note", "createdAt" }],
  "comments": [{ "id", "commenterId", "commenterName", "content", "createdAt" }],
  "attachments": [{ "id", "originalName", "sizeBytes", "uploaderName", "createdAt" }],
  "subtasks": [{ "id", "taskNo", "title", "status", "assigneeName", "dueAt", "progress" }],
  "mailRecords": [{ "id", "recipient", "subject", "result", "createdAt" }]
}
```

## 6. 错误码全表

| 码 | HTTP | 含义 | details |
|---|---|---|---|
| 0 | 200 | 成功 | — |
| 1001 | 400 | 参数校验失败 | 逐字段错误 `[{ "field", "reason" }]` |
| 1002 | 404 | 资源不存在 | — |
| 1003 | 429 | 触发限流 | `{ "retryAfterSeconds": 60 }` |
| 1004 | 400 | 非法请求（如同时携带两种凭证） | — |
| 2001 | 403/404 | 任务不存在或不可见（不区分，防探测） | — |
| 2002 | 400 | 非法状态流转（前置状态不满足） | `{ "currentStatus", "requiredStatus" }` |
| 2003 | 400 | 操作人身份不符（非处理人/非创建人） | — |
| 2004 | 400 | 存在未完成子任务，禁止提交验收 | `{ "unfinishedCount": 2 }` |
| 2005 | 400 | 任务已归档，只读 | — |
| 2006 | 400 | 删除仅限待办状态 | — |
| 2007 | 400 | 处理人不合法（admin / 已停用 / 不存在） | — |
| 2008 | 400 | 附件超限 | `{ "limit": "size\|count\|type", "detail": "..." }` |
| 2009 | 400 | 进度值非法（非 0-100 步进 5） | — |
| 2010 | 400 | 导出行数超上限（10000 行） | — |
| 2011 | 400 | 父任务非法（不存在 / 非顶层） | — |
| 2012 | 400 | 导入校验失败，整批未入库 | 逐行错误 `[{ "row", "reason" }]` |
| 3001 | 403 | 缺少权限点 | `{ "required": "exportData", "roleKey": "user" }` |
| 3002 | 401 | 账号或密码错误 | `{ "remainingAttempts": 3 }` |
| 3003 | 401 | 账号锁定中（15 分钟） | `{ "unlockAt": "..." }` |
| 3004 | 401 | 账号已停用 | — |
| 3005 | 401 | 令牌无效或已过期 | — |
| 3006 | 401/403 | API Key 无效、已停用或无权访问该接口 | — |
| 3007 | 400 | 账号已存在 | — |
| 3008 | 400 | 部门存在在职用户，不可删除 | `{ "userCount": 5 }` |
| 3009 | 400 | admin 的 manageUser / setPerm 不可关闭 | — |
| 4001 | 403 | 通知不存在或非本人 | — |
| 5000 | 500 | 服务端内部错误 | `{ "traceId": "..." }` |

> 安全约定：`2001` 对"不存在"与"不可见"返回同一错误码，防止遍历 id 探测他人任务是否存在（配合 PRD 验收标准"越权访问返回 403"）。

## 7. 与 PRD 6.1 的对照及差异
